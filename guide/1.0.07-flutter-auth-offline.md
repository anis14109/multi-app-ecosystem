# 1.0.05-flutter-auth-offline

Step-by-step guide for the **Hybrid Offline-First Authentication & Local Lock** feature added to `sirikotia-flutter-app`, backed by new **Laravel Sanctum** API endpoints in `sirikotia-laravel-api`.

The app now authenticates against the Laravel API and stores credentials **locally** so it works fully offline. A local **PIN (6-digit) or Biometric** (fingerprint / Face ID) unlock layer protects the app when reopened or used without internet.

Source prompt: [`guide/prompt/1.0.05-flutter-auth-offline.txt`](prompt/1.0.05-flutter-auth-offline.txt)

### 3.9. NEW core services (`lib/core/services/`)

**`api_client.dart`** — Dio with automatic Bearer token and 401-refresh interceptor (lines 16–36):

```dart
ApiClient({
  required SecureStorageService secureStorage,
  required String baseUrl,
}) : _secureStorage = secureStorage {
  _dio = Dio(
    BaseOptions(
      baseUrl: baseUrl,
      connectTimeout: const Duration(seconds: 15),
      receiveTimeout: const Duration(seconds: 15),
      headers: {
        'Accept': 'application/json',
        'Content-Type': 'application/json',
      },
    ),
  );
  _dio.interceptors.add(_AuthInterceptor(_secureStorage, _dio));
}
```

On `401` the interceptor silently refreshes using the `refresh_token`. If refresh fails, **only tokens are cleared** — PIN, biometric flag, and user data are preserved so offline unlock still works.

**`secure_storage_service.dart`** (full, lines 1–181) — splits storage into two categories:
- **Server tokens** (`access_token`, `refresh_token`): cleared by the interceptor on refresh failure.
- **Local auth data** (PIN hash, biometric flag, user data): only cleared on explicit logout.

Key method `hasCompletedLocalSetup()` (lines 145–151) — the primary offline lock check:

```dart
Future<bool> hasCompletedLocalSetup() async {
  final userId = await getUserId();

  final hasPin = await hasPinCreated();
  if (hasPin) return true;
  return isBiometricEnabled();
}
```

### 3.11. Auth flow state machine

```text
App launch ──> AuthStarted
  ├─ No user data ─────────────> AuthUnauthenticated (login page)
  ├─ Data, no PIN/biometric ───> AuthSetupRequired (choose method)
  └─ Data + PIN/biometric ─────> AuthLocalLocked (lock screen)

Lock screen ──> verify PIN (LOCAL) or Biometric (OS)
  └─ success ──> check connectivity
       ├─ online  ──> AuthenticatedOnline
       └─ offline ──> AuthenticatedOffline
```

```php
private function generateTokenPair(User $user): array
{
    // Short-lived access token (expires in 1 day).
    $accessToken = $user->createToken(
        'access_token',
        ['access-api'],
        now()->addDays(1),
    )->plainTextToken;

    // Long-lived refresh token (expires in 180 days).
    $refreshToken = $user->createToken(
        'refresh_token',
        ['issue-access-token'],
        now()->addDays(180),
    )->plainTextToken;

    return [
        'access_token' => $accessToken,
        'refresh_token' => $refreshToken,
        'token_type' => 'Bearer',
    ];
}
```

## 7. Biometric Unlock — Android Fingerprint / Face ID fix (`multi-app-ecosystem/flutter-app`)

The same local unlock layer described above is also implemented in the separate `multi-app-ecosystem/flutter-app` (package `flutter_app`). This section pins the exact files and semantics that make the **OS fingerprint / Face ID popup** actually appear when the user taps the biometric unlock button.

### 7.1. Root cause (Android only)

`local_auth` on Android requires the host activity to extend
**`FlutterFragmentActivity`** (a documented plugin requirement on Android).
The broken app extended the default `FlutterActivity`, so the OS biometric
dialog never attached and tapping the button silently did nothing.

The **Dart layer was already identical** to the working reference app —
`BiometricService.authenticate()`, the bloc handler, the lock screen
dispatch, pubspec `local_auth: ^2.3.0`, the Android manifest permissions,
and the iOS Face ID keys were all byte-for-byte the same. The single
difference was the Android host activity.

### 7.2. Modified — `android/.../MainActivity.kt` (full, lines 1–5)

```kotlin
package com.example.verygoodcore.flutter_app

import io.flutter.embedding.android.FlutterFragmentActivity

class MainActivity : FlutterFragmentActivity()
```

> **THE FIX.** Changing the base class from `FlutterActivity` to
> `FlutterFragmentActivity` is what makes the fingerprint / Face ID popup
> open. The default `flutter create` template generates `FlutterActivity`.

### 7.3. Modified — `android/app/src/main/AndroidManifest.xml` (lines 2–9)

```xml
    <!-- Required to communicate with the Laravel API. -->
    <uses-permission android:name="android.permission.INTERNET"/>
    <!-- Required for fingerprint / face unlock via local_auth (API 28+). -->
    <uses-permission android:name="android.permission.USE_BIOMETRIC"/>
    <!-- Required for fingerprint unlock on Android 8.1 (API 27) and below. -->
    <uses-permission android:name="android.permission.USE_FINGERPRINT"/>
```

- `INTERNET` — allows the app to reach the Laravel API over HTTPS.
- `USE_BIOMETRIC` (API 28+) / `USE_FINGERPRINT` (API ≤ 27) — `local_auth`
  prompts the OS dialog only when one of these is declared.

Also set on `<application>`: `android:usesCleartextTraffic="true"` for local
`http://` API addresses during development.
