# 1.0.06-install-flutter-app

Step-by-step guide to create, configure, and build the `flutter-app` Flutter application. The folder is named `flutter-app` while the Dart/Android package name remains `flutter_app` (hyphens are not valid in Dart package names).

---

## Step 1: Create Flutter App Scaffold

```bash
very_good create flutter_app flutter_app
```

Generates 195 files using the Very Good CLI `android-flavors` template, which provides three flavors: `production`, `staging`, and `development`.

---

## Step 2: Rename Folder

```powershell
Rename-Item -LiteralPath "flutter_app" -NewName "flutter-app"
```

---

## Step 3: Navigate Inside Flutter App

```bash
cd flutter-app
```

---

## Step 4: Fetch Dependencies

```bash
very_good packages get --recursive
```

---

## Step 5: Fix Kotlin Version

The Very Good CLI template ships with Kotlin `2.2.10`, which is below Flutter's minimum supported version of `2.2.20`. Two files must be updated before the build will succeed.

### 5.1. `android/settings.gradle.kts` (line 22)

**Before:**

```kotlin
    id("org.jetbrains.kotlin.android") version "2.2.10" apply false
```

**After:**

```kotlin
    id("org.jetbrains.kotlin.android") version "2.2.20" apply false
```

### 5.2. `android/app/build.gradle.kts` (line 97)

**Before:**

```kotlin
    implementation("org.jetbrains.kotlin:kotlin-stdlib:2.2.10")
```

**After:**

```kotlin
    implementation("org.jetbrains.kotlin:kotlin-stdlib:2.2.20")
```

Without this fix the build fails with:
> Error: Your project's Kotlin version (2.2.10) is lower than Flutter's minimum supported version of 2.2.20.

---

## Step 6: Remove Generated `.github/` Folder

```powershell
Remove-Item -Path ".github" -Recurse -Force
```

---

## Step 7: Generate Release Keystore

Generate a release keystore using the Android Studio JBR keytool (RSA 2048-bit, 10,000-day validity):

```powershell
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkey -v `
  -keystore android/app/release-key.jks -keyalg RSA -keysize 2048 `
  -validity 10000 -alias flutterapi `
  -storepass flutterapi123 -keypass flutterapi123 `
  -dname "CN=Sirikotia, OU=Development, O=Sirikotia, L=Unknown, ST=Unknown, C=ID" `
  -storetype PKCS12
```

This creates `android/app/release-key.jks`.

---

## Step 8: Create `android/key.properties`

Create the signing credentials file referenced by `android/app/build.gradle.kts` (line 11):

```
storePassword=flutterapi123
keyPassword=flutterapi123
keyAlias=flutterapi
storeFile=release-key.jks
```

Without this file (or the corresponding `ANDROID_KEYSTORE_*` environment variables), the release build fails with:
> SigningConfig "release" is missing required property "storeFile".

---

## Step 9: Create `android/app/proguard-rules.pro`

The release build type has `isMinifyEnabled = true` and references `proguard-rules.pro` in `build.gradle.kts` (line 83). Create this file with Flutter-specific rules:

```pro
# Flutter-specific proguard rules
-dontwarn io.flutter.plugin.**
-dontwarn android.**

-if class * implements io.flutter.embedding.engine.plugins.FlutterPlugin
-keep,allowshrinking,allowobfuscation class <1>
```

## Step 11: Build Production APK

```bash
flutter build apk --flavor production --target lib/main_production.dart --target-platform android-arm64
```

**Output:**

```text
√ Built build\app\outputs\flutter-apk\app-production-release.apk (15.0MB)
```

- **Flavor:** `production` (applicationId `com.example.verygoodcore.flutter_app`)
- **Target platform:** `android-arm64`
- **Target file:** `lib/main_production.dart`
- **Release signing:** `release-key.jks` via `android/key.properties`
- **Minification:** enabled (`isMinifyEnabled = true` with proguard rules from Step 9)

## Notes

- Do not commit `android/key.properties` or `android/app/release-key.jks` to version control
- To regenerate the keystore for production release, replace the values in `android/key.properties` with your own credentials
- Build warnings about Gradle 9.0.0 / AGP 8.12.0 / Kotlin 2.2.20 reaching end-of-support are informational only
