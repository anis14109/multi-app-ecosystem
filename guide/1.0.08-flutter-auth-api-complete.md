## Error Handling Architecture

A typed exception hierarchy replaces raw `DioException` handling:

### New: `lib/core/errors/api_exception.dart`

```dart
// lib/core/errors/api_exception.dart (lines 14–55)
class ApiException implements Exception {
  const ApiException({
    required this.message,
    required this.statusCode,
    this.code,
    this.errors = const <String, List<String>>{},
  });

  final String message;
  final int statusCode;
  final String? code;
  final Map<String, List<String>> errors;

  String? get firstFieldError {
    for (final messages in errors.values) {
      if (messages.isNotEmpty) return messages.first;
    }
    return null;
  }
}

class ValidationException extends ApiException { ... }
class AuthenticationException extends ApiException { ... }
class AuthorizationException extends ApiException { ... }
class RateLimitException extends ApiException { ... }
class NetworkException extends ApiException { ... }
class ServerException extends ApiException { ... }
```

The `mapApiException(DioException)` mapper (lines 119–171) parses the
Laravel v1 envelope `{success, message, code, errors}` and produces the
correct typed exception based on HTTP status code.

## Token Refresh Improvements

The `_AuthInterceptor` (in `lib/core/services/api_client.dart`) was
reworked with:

### Single-flight refresh interceptor

```dart
// lib/core/services/api_client.dart (lines 203–282)
class _AuthInterceptor extends Interceptor {
  _AuthInterceptor(this._secureStorage, this._dio);

  final SecureStorageService _secureStorage;
  final Dio _dio;

  static const String _retriedKey = '_auth_retried';
  Future<bool>? _refreshInFlight;

  static bool _isPublicEndpoint(String path) {
    return path.contains('/auth/login') ||
        path.contains('/auth/register') ||
        path.contains('/auth/refresh') ||
        path.contains('/auth/forgot-password') ||
        path.contains('/auth/reset-password') ||
        path.contains('/auth/email/verify');
  }
```

1. **Single-flight refresh**: simultaneous 401 responses share one
   refresh future via `_refreshInFlight`, preventing TOKEN_REUSED
   revocation.
2. **Retry guard**: each request carries `_auth_retried` in
   `requestOptions.extra` to prevent infinite loops.
3. **Public endpoint skip**: login, register, refresh, forgot-password,
   reset-password, and email-verify never attach Authorization headers.
4. **Failure policy**: transient network errors preserve both tokens;
   permanent HTTP rejections clear both tokens and preserve local auth
   (PIN, biometric, user data).

### Transport failure policy

```dart
// lib/core/services/api_client.dart (lines 329–345)
    } on DioException catch (error) {
      final isTransportFailure =
          error.type == DioExceptionType.connectionTimeout ||
          error.type == DioExceptionType.sendTimeout ||
          error.type == DioExceptionType.receiveTimeout ||
          error.type == DioExceptionType.connectionError;

      if (error.response == null || isTransportFailure) {
        // Transient failure: the tokens may still be valid.
        return false;
```

## Feature Architecture

Sub-flow pages (forgot password, reset password, email verification,
password confirmation) use their own **dedicated Cubits** rather than
adding states to `AuthBloc`. This avoids the `AuthWrapper` default
fallback rendering `LockScreen` for unknown states.

The `AuthBloc` now handles `AuthLogoutAllRequested` for the "log out of
all devices" action, which revokes all sessions and clears local auth.

`AuthRepository` is provided to the widget tree via
`MultiRepositoryProvider` in `App`, and each feature page reads it from
`context.read<AuthRepository>()` when constructing its cubit.

## Bug Fix: Registration → Setup Redirect

### Problem

After successful registration, the app stayed on `RegisterPage` instead
of redirecting to `SetupPage`. The root cause: `RegisterPage` was pushed
via `Navigator.pushNamed('/register')` on top of the root `AuthWrapper`
route. When `AuthBloc` emitted `AuthSetupRequired`, the `AuthWrapper`
below correctly transitioned to `SetupPage`, but the pushed
`RegisterPage` was never popped — it covered the new screen.

### Solution

Added a `BlocListener` around the `Scaffold` that calls
`Navigator.of(context).pop()` when `AuthSetupRequired` is reached,
returning the user to the root route where `AuthWrapper` shows
`SetupPage`.

### Modified: `lib/auth/view/register_page.dart`

## Other Sub-Flow Pages (No Same Bug)

Analysis of pushed sub-flow pages confirms they do NOT have the same
navigation bug, because their cubits are self-contained and never change
`AuthBloc` state:

|---|---|---|---|
| ForgotPasswordPage | `ForgotPasswordSuccess` | No | Manual "Back to Login" |
